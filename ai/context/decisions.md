# catalyst-commerce — decisions

The choices that shape this repository, one line each, with where the full
reasoning lives. Superseded decisions stay listed, marked, so the history
reads in order.

| # | Decision | Why | Source |
|---|---|---|---|
| 1 | OpenNext on Workers + Static Assets, the commerce baseline's shape | Catalyst is a Next.js App Router app: route handlers, server actions and the proxy run in the Worker | `specs/epics/catalyst-commerce/design.md` |
| 2 | The incremental cache in R2, the tag cache (sharded) and the revalidation queue in Durable Objects | The commerce baseline's proven shape; Catalyst caches through Next's fetch cache (`revalidate`, `tags`), not Cache Components, so nothing is turned off | the spike |
| 3 | Catalyst's own Cloudflare KV adapter for its route lookups, in a namespace Terraform provisions (kv-redis-starter's root) | Upstream ships the adapter (`lib/kv/adapters/cloudflare-kv.ts`, `CATALYST_ROUTES_KV`) | the spike |
| 4 | Next.js 16.3.8 (inside upstream's `~16.3.4`), built with webpack | @opennextjs/cloudflare 1.20.11 supports `>=16.3.8`; with Turbopack its middleware bundle cannot resolve `@opentelemetry/api` | the spike |
| 5 | The GraphQL types from BigCommerce's published Storefront schema (`apps/web/bigcommerce.graphql`, from bigcommerce/checkout-sdk-js), not the live store | The build, type check, lint and tests then need no store; `generate:schema` refreshes it from a connected one | IMPLEMENTATION-STATUS |
| 6 | No store, no calls: one connection seam (`lib/bigcommerce-connection.ts`); unconnected, `/` says "Connect your BigCommerce store" and the proxy and the storefront layout send everything else there | A baseline goes live before its owner has a store, never with a 500 | IMPLEMENTATION-STATUS |
| 7 | The store's hash, token and channel are OPTIONAL secrets, read by the build and set as Worker secrets by the deploy | The build reads the store's settings (site, checkout, CDN URLs, robots.txt, sitemap); every request reads the store | `apps/web/component.yaml` |
| 8 | Auth.js's key generated by the Worker and kept in its KV namespace unless `AUTH_SECRET` is set (`worker.ts`, `lib/auth-secret.ts`) | Nothing to type, never in a repository; no database to generate it in | design |
| 9 | One store-name seam (`SITE_NAME`, `lib/site.ts`) as the fallback name; the connected store's name wins | Catalyst names the store from BigCommerce's settings; the rename rewrites one line | IMPLEMENTATION-STATUS |
| 10 | `@vercel/otel` loaded only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set | At module scope it fails every request on workerd | the spike |
| 11 | The lockfile seeded from upstream's (its `core` importer moved to `apps/web`); typescript-eslint held at upstream's 8.28 | Upstream's tested resolutions; a newer typescript-eslint brings rules its sources were never linted with | IMPLEMENTATION-STATUS |
| 12 | The e2e connects a stand-in BigCommerce (`testing/lib/fake-bigcommerce.mjs`): graphql-js over the published schema, one default resolver by type and name | It answers every query the storefront sends without a list of them | `testing/e2e.test.sh` |
| 13 | stack-tectonic 0.19.0, `ci.yml` as the commerce baseline's, no `checks.yml`, the domain not asked, the subdomain from the Cloudflare connection | The commerce baseline's settled shape | `intent.yaml` |
| 14 | Workers Paid is a stated requirement | The Worker is 3.4 MiB gzipped; trimming Catalyst's features to fit Free would change the product | risk CA-B |
